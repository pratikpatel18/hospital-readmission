# Model Card - 30-Day Patient Readmission Risk

## Model details
- **Task:** binary classification - will a discharged patient be readmitted within 30 days?
- **Final model:** `xgboost` (tuned with RandomizedSearchCV, time-ordered CV, scoring = PR-AUC), wrapped in one scikit-learn pipeline (feature engineering -> imputation -> encoding -> scaling -> model).
- **Intended users:** nurses / care coordinators of the (fictional) Pune community-clinic network, through a Streamlit screen backed by a FastAPI service.
- **Intended use:** rank discharged patients for a follow-up call / early OPD slot. **Not** a diagnostic tool; it must not be used to deny or delay care.

## Data
- **IMPORTANT:** data is **synthetic** (generated by `src/data_generation.py`) and mimics the brief: 4 hospitals, ~500k rows across OPD visits, admissions, lab tests and billing; GST counted twice in some bills, missing discharge dates, free-text diagnosis.
- **Cleaning:** GST double-count detected (total = base + 2xGST) and corrected; free-text diagnosis mapped to 9 groups with rules; missing discharge date -> LOS/discharge weekday imputed in the pipeline; admissions in the last 45 days dropped (follow-up window incomplete).
- **Split:** chronological by admission date - train 2024-04-24 / validation 2024-08-05 / test 2024-11-16 (59,161 / 12,677 / 12,678 rows). History features (prior admissions, OPD visits) only count events strictly before admission, so there is no leakage.
- **Class imbalance:** about 14% positives; handled with class weights / `scale_pos_weight`.

## Performance (held-out, later-in-time test set)
| Metric | Final model | Baseline: rank by prior admissions (current practice) | Untuned logistic regression |
|---|---|---|---|
| PR-AUC (chosen metric) | **0.462** | 0.191 | 0.443 |
| ROC-AUC | 0.802 | 0.604 | 0.797 |

- **Baseline definition:** the brief does not define it, so we use the simple rule clinic staff can apply today (rank by admissions in the last 180 days). Improvement over this baseline: **141.4%** (target >= 20%) -> met.
- Honest note: against the untuned logistic regression (a much stronger benchmark) the gain is only 4.1%. Versus random (prevalence 0.140) PR-AUC is 231% higher.
- Why PR-AUC: with ~13% positives, ROC-AUC looks flattering; PR-AUC measures how well the top of the list is filled with real readmissions, which is what staff act on.
- API latency incl. SHAP explanation: ~15 ms (target < 300 ms) -> met.

## Threshold choice (business terms)
Staff can only call so many patients, and every call costs money, so the threshold comes from costs, not from 0.5.

| Outcome | Cost (INR) | Meaning |
|---|---|---|
| False negative | 40,000 | readmitted patient we did not flag |
| False positive | 1,500 | follow-up call made for nothing |
| True positive | 29,500 | follow-up (1,500) + the 70% of readmissions it fails to prevent |
| True negative | 0 | nothing to do |

- Rule of thumb: flag a patient when the true risk exceeds 1,500 / (30% x 40,000) = **12.5%**. Because class weighting inflates raw scores, the exact cut-off was found by scanning thresholds on the validation set and minimising total cost: **0.51**.
- On the test set this flags 34% of discharges, catches 73% of readmissions (precision 30%).
- Total cost INR 61,660,500 vs INR 70,800,000 if nobody is flagged and INR 61,681,500 with the default 0.5 threshold - a saving of about INR 720,894 per 1,000 discharges (under the stated assumptions).
- If the clinics' call capacity or cost assumptions change, rerun `python -m src.train`; the threshold is recomputed.

## Monitoring
`src/drift.py` compares incoming data with a training reference sample (PSI + KS test) for key features and logs a WARNING to `logs/drift.log` when they shift (PSI > 0.2 or significant KS). The API exposes `GET /drift`.

## Limitations and ethics
- Trained on synthetic data - metrics show the engineering works, **not** clinical validity. Re-validate on real data, by hospital and by age/sex subgroup, before real use.
- Probabilities are not calibrated (class weights); treat them as a risk ranking, or add calibration before showing percentages to patients.
- Diagnosis mapping is rule-based and will miss unseen spellings (-> "other").
- Readmissions to other hospitals are invisible. Sex is used as a feature; review for fairness before deployment.
- Human oversight: a flag triggers a *follow-up*, never a change in treatment.
